address: mongolia.tax.tin
description: The Mongolian taxpayer number of a LEGAL person — seven digits, no letters, no country prefix, no separator. It is the same number as the company's регистрийн дугаар: Mongolia assigns one number at state registration and the General Department of Taxation then uses it as the tax identifier, so registration number and tax number are the same seven digits and a schema carrying both as separate columns for a Mongolian company will find them equal in every row. THAT IS THE CORRECT ANSWER AND NOT A BUG. A natural person does not have one of these at all: an individual, including a sole trader, is identified to the tax authority by the ten-character mongolia.docs.registrationNumber, which is why a "taxpayer id" column in Mongolian data is seven characters for some rows and ten for others, with letters in the ten-character ones. A schema that types that column as an integer has silently excluded every individual taxpayer in the country. NO CHECK DIGIT IS GENERATED HERE. Mongolia publishes no checksum specification for the seven-digit number, the tax authority validates it by lookup against the register rather than by arithmetic, and there is no Mongolia module in python-stdnum, the usual home for national-identifier algorithms — so inventing a mod-11 would make this file look verified while rejecting real numbers. The leading digit is left unconstrained for the same reason: secondary sources describe the number only as "a unique seven-digit numeric code assigned upon incorporation", with no documented rule about ranges or prefixes, so nothing narrower is claimed. Note also that Mongolia issues a separate and longer улсын бүртгэлийн дугаар (state registration number) alongside it, which appears on company certificates and is NOT this number; its format is not documented in any source this file was checked against, so it is not generated anywhere in this pack.
