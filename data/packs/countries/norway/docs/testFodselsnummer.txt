address: norway.docs.testFodselsnummer
description: A SYNTHETIC Norwegian identity number in the form the Norwegian state itself uses for testing — a fødselsnummer with 80 ADDED TO THE MONTH, so the month digits read 81–92 instead of 01–12. This is not a convention invented here: it is the rule Skatteetaten's Tenor test register and Digdir's ID-porten TestID both run on ("syntetisk personidentifikator, +80 på måned-sifrene"), and it exists to solve exactly the problem a data generator creates. A generator that emits well-formed real-format fødselsnummer will, given enough rows, emit a number that belongs to a living person — the format has only about 700 issuable numbers per birth date, so collision is not a remote possibility but an arithmetic certainty at scale — and that number will then pass every validator, resolve in every lookup, and quietly contaminate a production system. The +80 month cannot belong to anyone, because no one is born in month 87, yet everything else about the number is right: the individnummer still encodes the century by range, the last individ digit still encodes sex, and BOTH modulus-11 check digits are computed normally over the offset month, so a synthetic number passes a correct validator and is rejected by a date parser. Use this address when the data may ever leave a sandbox, and norway.docs.fodselsnummer when the format has to be exactly what production sees. Draws whose check digit computes to 10 are unissuable and are redrawn here too. Note that the +80 offset stacks with nothing: it is applied to the month, while the D-number's +40 is applied to the day, so the two conventions are independent and both can be recognised on sight.
generator: tdc
locale: nb
