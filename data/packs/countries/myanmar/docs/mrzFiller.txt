address: myanmar.docs.mrzFiller
description: The ICAO 9303 filler character '<', fourteen of them — the width of the optional-data field of a TD3 machine-readable zone. IT EXISTS FOR A HOUSEKEEPING REASON AND NOT A NATIONAL ONE, and the reason is worth writing down where the next person will find it: the run is NAMED, so the passport config draws it by address instead of repeating a literal and the width is stated in one place. Nothing forces it — a config can hold the character directly, `<gen type="text" value="<<<<<<<<<<<<<<"/>` emits fourteen of them, and `<` is an ordinary character in an attribute value. An earlier version of this note claimed the opposite, that the character could not be produced from a config at all; it could, and the claim is gone. myanmar.docs.passportMrz draws the run from here and slices a single character off it for the one-column pad after the document number. If entity decoding is ever added to the parser, this file can go and the `<str>` form can be used instead. Nothing about Myanmar is encoded here; the filler is the same on every ICAO travel document in the world.
