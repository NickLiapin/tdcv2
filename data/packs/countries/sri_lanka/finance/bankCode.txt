description: The 4-digit bank code allotted by LankaClear, the Central Bank-owned operator of SLIPS and LankaPay, and the first half of every domestic routing key (see sri_lanka.finance.slipsCode). AND IT CARRIES A REAL CHECK DIGIT, which nobody publishes as one. The fourth digit is fully determined by the first three under the weights 7, 3, 1 taken mod 10, with the digit being (10 - sum mod 10) mod 10 — equivalently 7*d1 + 3*d2 + 1*d3 + d4 is a multiple of 10. Worked example: Sampath Bank is 7278, and 7*7 + 3*2 + 1*7 = 62, (10 - 2) mod 10 = 8, which is the digit printed. How this was established, because it matters more than the claim — the weights were fitted to 32 codes published by one directory and then tested against 13 further codes taken from two other directories and never used in the fit, including the Central Bank's own 8004, which is the only code in Sri Lanka that does not begin with 7. All 45 pass. A brute-force sweep of all 1,000 weight triples (w1,w2,w3) in 0-9 finds exactly ONE that satisfies every code, so the rule is unique rather than one plausible fit among several. And it catches everything a check digit is for: all 1,620 single-digit mutations of those 45 codes are rejected, with none slipping through — unlike the Bangladeshi routing check, whose weight of 5 blinds it to a whole class of errors. This file therefore draws from the 45 REAL allotted three-digit prefixes and COMPUTES the fourth digit rather than copying it, so every value is both a genuine in-service bank code and an independent demonstration of the arithmetic. Two honest limits. LankaClear does not describe this digit as a check digit in anything public, so the label is this pack's inference and the evidence above is why; and because the codes are drawn from the allotted set, a value here always names a real institution but the pack cannot say WHICH one in the same row as sri_lanka.finance.bank — a config that needs the name and the code to agree must hold the pairing itself.
