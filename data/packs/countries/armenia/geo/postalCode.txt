address: armenia.geo.postalCode
description: Armenian postal code — FOUR digits, and every one of the 427 codes below is a real HayPost delivery office taken from the operator's own published index of post offices, not a number drawn from a range. Armenia switched to four digits on 1 April 2006; before that it used the six-digit Soviet form, so the foreign ministry's 375010 became 0010 and any Armenian address carrying six digits is pre-2006. The leading zero is part of the code and Yerevan is entirely inside 0001-0108, so a system that stores postal codes as integers loses the whole capital. The first two digits are a geographic zone and they run in a clean band from the capital outwards: 00-01 Yerevan, 02-05 Aragatsotn, 06-08 Ararat, 09-11 Armavir, 12-16 Gegharkunik, 17-21 Lori, 22-25 Kotayk, 26-31 Shirak, 32-35 Syunik, 36-38 Vayots Dzor, 39-42 Tavush. The band stops at 4210 — there is no Armenian postal code above it, which is why this file ships the enumerated list rather than a 0001..9999 range: four fifths of that range addresses nowhere. Codes are NOT contiguous inside a zone either (0007, 0021, 0027 and 0030 are simply not issued), so incrementing a valid code does not give another valid code. Drawing is uniform over post offices, not over people: Yerevan holds 89 of the 427 offices, about 21 percent, against 37 percent of the population, so this file under-weights the capital relative to where Armenians actually live — use armenia.geo.city for population-shaped geography. AND THE DRAW IS INDEPENDENT: a row that takes a code from here and a town from armenia.geo.city will pair them at random, so 2208 (Kotayk) will land beside Գյումրի (Shirak) as often as chance allows. This pack ships no city-to-postcode mapping. Keeping a row internally consistent is the config's job — draw the zone you want and hold it, or pick the code first and constrain the town to its province using the zone bands above.
