DERIVED line for line from person/lastName.txt by the rule below — the two files are aligned row for row and must stay so, or a generated household gets a husband and a wife from different families. THE RULE, applied in this order: -скі / -цкі -> -ская / -цкая (Казлоўскі -> Казлоўская); a bare adjectival -ы -> -ая (Мірны -> Мірная, Чорны -> Чорная); -аў -> -ава, -оў -> -ова, -ёў -> -ёва, -еў -> -ева (Быкаў -> Быкава, Кавалёў -> Кавалёва, Някляеў -> Някляева); -ін / -ын take a plain -а (Барадулін -> Барадуліна); and EVERYTHING ELSE DOES NOT MOVE — the whole -іч / -віч patronymic family (Багдановіч stays Багдановіч), the -ка / -ко / -анка / -энка type (Каваленка, Скурко, Саўчанка), the -еня type (Герасіменя), the -онак / -ёнак type (Кавалёнак), the -ук / -юк / -чук type (Кавальчук), the -ік / -чык type (Новік, Адамчык) and the bare-noun surnames (Мароз, Заяц, Каваль, Бондар, Воўк, Бусел). Because only two of those branches move, roughly two lines in three are CHARACTER-FOR-CHARACTER THE SAME as the masculine file. That is correct Belarusian: пані Багдановіч and пан Багдановіч are spelled identically, and a config that tries to feminise every surname mechanically will produce strings no Belarusian registry has ever issued. Weights mirror person/lastName.txt exactly so that the two lists draw the same family at the same rank.
