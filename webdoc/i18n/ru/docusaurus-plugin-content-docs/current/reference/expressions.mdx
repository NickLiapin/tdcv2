# Выражения

Маленький язык внутри `if=` — и внутри `filter=` у [пула](../pools/filter.mdx), который
читается так же. Он решает, участвует ли `<gen>`, `<line>`, `<case>` или `<data>` в строке.

```xml
<sequence name="Zone">
  <gen if="Country in [US, CA, MX]" type="text" value="NAFTA"/>
  <gen if="Country in [FR, DE]"     type="text" value="EU"/>
  <gen                              type="text" value="ROW"/>
</sequence>
<sequence name="Handling">
  <gen if="Weight > 20"      type="text" value="freight"/>
  <gen if="_count % 2 == 0"  type="text" value="courier-even"/>
  <gen                       type="text" value="parcel"/>
</sequence>
```

<Terminal title="./run shipping.tdc">
{`US NAFTA 2kg parcel
FR EU 14kg courier-even
CA NAFTA 7kg parcel
DE EU 30kg freight
MX NAFTA 5kg parcel
JP ROW 22kg freight`}
</Terminal>

У последнего `<gen>` в каждой последовательности нет `if=`, поэтому он забирает всё, что не
подошло условиям выше, — та же форма, что и `else`.

## Значения

| Вы пишете         | Что это значит                                                             |
| :---------------- | :------------------------------------------------------------------------- |
| `Country`         | значение, которое эта последовательность дала на этой строке               |
| `Person.Email`    | поле [составной последовательности](../core-concepts/sequences.mdx)        |
| `Gender.Male`     | «сейчас Gender равен Male?» — читается как `parent="Gender.Male"`           |
| `Male`            | **голое слово**: имя, которое не является последовательностью, — это текст  |
| `42`, `1.5`       | число                                                                      |
| `'текст'`         | строка в кавычках, когда в тексте пробелы или он похож на имя              |
| `_count`, `_last` | [встроенное](builtins.mdx) — номер строки, признак последней               |

Голое слово — это то, что позволяет писать `Gender == Male` без кавычек. Оно же означает, что
**опечатка сравнивается сама с собой и молча ни с чем не совпадает**, — поэтому неизвестное
имя справа от точки даёт [TDC193](errors.mdx), а не проходит.

## Операторы

| Группа         | Операторы                        |
| :------------- | :------------------------------- |
| сравнение      | `== != === !== < > <= >=`        |
| логика         | `&& \|\| !`                      |
| арифметика     | `+ - * / %`                      |
| принадлежность | `in`                             |
| выбор          | `a ? b : c`                      |

:::caution[`%` евклидов, и это не то, что делает ваш язык]
`-3 % 2` здесь **1**. JavaScript, Java, C# и Rust отвечают −1; Python отвечает 1.

Причина не во вкусе. В [слое compute](compute.mdx) уже был `<mod>`, и он уже отвечал 1, — так
что `%`, взявший соглашение хозяина, заставил бы один движок давать два разных ответа на один
вопрос в зависимости от того, к какому слою вы потянулись.
:::

`in` берёт справа список и ничего кроме — список в любом другом месте даёт
[TDC259](errors.mdx). Сравнение внутри такое же нестрогое, как у `==`, поэтому текстовая
колонка против списка числовых слов всё равно совпадёт.

```xml
<gen if="Country in [US, CA, MX]" .../>   <!-- вместо трёх == через || -->
```

## Функции

Каждая функция здесь **точная**: собрана из сравнений и той арифметики, которую IEEE-754
задаёт однозначно, — поэтому пять реализаций не могут разойтись в результате.

| Функция                    | Берёт      | Даёт                                             |
| :------------------------- | :--------- | :----------------------------------------------- |
| `abs(x)`                   | 1          | модуль                                           |
| `ceil(x)` `floor(x)`       | 1          | вверх / вниз до целого                           |
| `trunc(x)`                 | 1          | к нулю — `trunc(-7.5)` это −7, а `floor` даёт −8 |
| `round(x)`                 | 1          | ближайшее, половина **от нуля**                  |
| `min(…)` `max(…)`          | 1 и больше | наименьшее / наибольшее                          |
| `len(s)`                   | 1          | сколько символов                                 |
| `is_empty(s)`              | 1          | пуст ли текст                                    |
| `starts_with(s, p)`        | 2          | проверка префикса                                |
| `ends_with(s, p)`          | 2          | проверка суффикса                                |
| `contains(s, p)`           | 2          | проверка вхождения                               |
| `lower(s)` `upper(s)`      | 1          | регистр                                          |

:::note[Два правила, которые стоит знать, прежде чем на них опираться]
**`round` отправляет половину от нуля.** `round(0.5)` это 1, а `round(-0.5)` это −1.
JavaScript округляет половину к +∞, Python — к чётному, Java — вверх: три хозяина, три
ответа, ни одного симметричного. TDC называет своё правило, чтобы колонка отрицательных вела
себя как колонка положительных.

**`len` считает кодовые точки.** `len("😀")` это 1, а не 2, которые дал бы UTF-16, — но
семейный эмодзи, собранный из нескольких кодовых точек, посчитается как несколько. Графемы
были бы человеческим ответом, но им нужна таблица сегментации Unicode, которую не всякая
реализация может нести, — поэтому побеждает переносимая единица. `len("10")` это 2: строковая
функция читает аргумент как текст, а не как число.
:::

## Чего нет намеренно

**Тригонометрия, логарифмы, степени.** `sin`, `cos`, `exp`, `log`, `sqrt` и им подобные
отвергаются по имени, с причиной:

<Terminal title="tdcv2 check seasonal.tdc">
{`error[TDC257]: cos() is not available yet in an if expression`}
</Terminal>

Примечание рядом объясняет почему, и причина измерима: `tan(1)` уже расходится в последнем
бите между Node и Python на одной машине. Из семидесяти семи взятых значений шестнадцать
расходятся хотя бы у двух реализаций из пяти. В `timeseries` этого не видно, потому что каждое
число округляется до того, как стать выводом, — а у сравнения шага округления нет, поэтому
один бит превращается в другую строку и другой файл. Они появятся, когда TDC станет считать
их сам, — так же, как он сам считает случайные числа, вместо того чтобы доверять каждому
языку.

**Циклы и рекурсия.** Движок выбирается по конфигу до генерации первой строки,
[`preflight()`](../guides/large-outputs.mdx) оценивает память до прогона, а `--jobs` режет
строки между воркерами. Всем троим нужно знать работу на строку, не выполняя её. Цикл ломает
все три сразу, а то, ради чего к циклу тянутся — «чётная ли это строка?», — это `%`.

**Побитовые операторы.** `_count & 1` — это `_count % 2`, записанное для машины. Они
разбираются, чтобы сообщение могло назвать их по имени, и затем отвергаются.

## Когда выражения не хватает

У [последовательности `<compute>`](compute.mdx) есть целочисленное деление, остатки, работа со
строками, кодировки и контрольные цифры. Она даёт значение, как любая другая
последовательность, и `if=` затем сравнивает уже его:

```xml
<sequence name="Checksum">
  <compute><result><mod><to_number><field name="Account"/></to_number><int v="97"/></mod></result></compute>
</sequence>
<sequence name="Flag">
  <gen if="Checksum == 0" type="text" value="divisible"/>
  <gen type="text" value="."/>
</sequence>
```

## Конфиг похож на XML, но это не XML

TDC не разворачивает сущности, поэтому `&lt;` — это четыре обычных символа, а не `<`. Пишите
символ напрямую:

```xml
<gen if="Weight > 20" .../>      <!-- да -->
<gen if="Weight &gt; 20" .../>   <!-- нет: TDC100, и сообщение объяснит почему -->
```
