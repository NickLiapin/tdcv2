# Работа с агентом

## Просите обычными словами

Опишите данные так, как описали бы коллеге:

```text
500 клиентов из 20 стран в CSV.
Тест на pytest для validate_user на 50 разных пользователях.
SQL-вставки для клиники: отделения, врачи в каждом отделении и их приёмы.
Тот же файл заказов, но 10 000 строк, и 30% из них отменены.
```

Скажите, что для вас важно: формат, сколько строк, какие поля должны сходиться друг с
другом, нужные доли, язык или страну. Всё, что вы не указали, агент решает сам и записывает
в конфиг, где вы это увидите.

## Что делает агент

1. Один раз за сессию читает руководство по TDC.
2. Ищет реальные значения в [пакетах данных](../data-packs/overview.md#top) — имена, города,
   IBAN. Если нужного языка или страны нет, ставит пакет; с MCP-сервером клиент сначала
   спрашивает вашего разрешения.
3. Пишет конфиг `.tdc` и проверяет его движком, пока не останется ни одной ошибки.
4. Генерирует превью первых строк или весь файл.
5. Кратко описывает файл — число строк, распределение каждого столбца, диапазоны, — чтобы
   показать, что в нём то, что вы просили.
6. Отдаёт вам файл и конфиг.

Только со скиллом агент делает всё это командой `tdcv2` в своём терминале. С MCP-сервером
он вместо этого вызывает инструменты сервера.

## Инструменты сервера

| Инструмент       | Что делает                                                                              |
| :--------------- | :-------------------------------------------------------------------------------------- |
| `tdc_read_docs`  | руководство, ловушки, которые `check` не ловит, тестовый код на пяти языках, любая страница этой документации |
| `tdc_find_packs` | ищет установленные пакеты данных по словам («фамилия», «iban») и даёт их адреса         |
| `tdc_pack_add`   | ставит пакеты для другого языка или страны — `tdcv2 pack add`                            |
| `tdc_check`      | все диагностики с кодом, строкой, столбцом, подсказкой и «возможно, вы имели в виду»    |
| `tdc_generate`   | превью до 50 строк или весь файл                                                        |
| `tdc_peek`       | краткое описание файла CSV, JSON или SQL в проекте                                      |
| `tdc_format`     | форматирует конфиг так же, как `tdcv2 format`                                           |

Ещё сервер даёт руководство как подсказку (prompt) `tdcv2_guide` и четыре страницы как
ресурсы: `tdcv2://guide`, `tdcv2://traps`, `tdcv2://from-code` и `tdcv2://linked-tables`.

## Проверьте результат

Сохранять стоит конфиг. Это короткий файл, в котором записано каждое правило, по которому
построены данные, и прочитать его быстрее, чем сами данные, — что вы в нём увидите,
объясняет страница [Первый датасет](../getting-started/first-data.md#top). Держите его в
проекте рядом с файлом, который он создал.

Один и тот же конфиг с тем же сидом даёт тот же файл байт в байт. Запустите его сами, без
агента:

```bash
npx -y tdcv2@0.3.5 customers.tdc -o customers.csv
```

Чтобы изменить данные, меняйте конфиг: попросите агента («сделай 10 000 строк, треть — из
Германии») или отредактируйте файл и запустите его снова. `tdcv2 check customers.tdc`
скажет, правильна ли правка, ещё до генерации.
